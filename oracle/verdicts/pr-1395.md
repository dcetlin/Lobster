## Stage 1 — Vision Alignment (written before seeing diff)

**Theory of change:** Subagent code quality will improve if subagents read golden-patterns.md before writing code. The theory is: awareness of proven patterns → better first-pass code → fewer oracle NEEDS_CHANGES rounds.

**Instruction-accumulation pattern (learnings.md 2026-04-22, cited as active prior):** This pattern constrained my analysis in a specific way: I checked whether the change adds growing context to the bootup document before evaluating implementation quality. The learning states that adding rules to fix behavioral failures is self-defeating when context growth is the root cause. This caused me to ask "is golden-patterns.md bounded?" (it is not — it is append-only) and "does this affect all subagents or only code-writing ones?" (it affects all). Without this prior, I would have evaluated the change as a reasonable quality improvement. With it, the unbounded growth and untargeted scope became the central concern.

**Principle-5 (vision.yaml, cited as active prior):** "Discriminator improvement over rule addition" constrained my assessment of whether the right fix layer is subagent bootup vs. oracle review. The oracle already reads golden-patterns.md and catches violations. Adding the same read to subagents is defense-in-depth, but principle-5 says the fix should improve the discriminator (oracle), not add more rules (subagent bootup). This shifted my assessment from "helpful defense-in-depth" to "rule addition that the vision explicitly cautions against."

**What would have to be true:** Subagents would need to be frequently violating golden patterns in ways that are expensive to fix at oracle review. The patterns would need to be generic enough to be actionable for arbitrary code tasks (not just steward/registry work). The context cost would need to be lower than the cost of oracle NEEDS_CHANGES rounds.

**What this forecloses:** Sets a precedent that bootup documents are the right place for quality-improvement context. Creates a growth vector where every quality-relevant file gets added to bootup, contributing to context pressure.

**Alignment verdict:** Questioned. The intent (better code quality) serves the vision. The mechanism (instruction accumulation in bootup doc) is in tension with the vision's own operating principles.
