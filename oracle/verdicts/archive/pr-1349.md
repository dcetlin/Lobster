### Flagged area 1: `_is_structural_child` detection criteria

The oracle pre-read from the task prompt asked to verify whether "section-label", "comment-area", h1/h2/h3 covers all structural child types.

**Finding: Detection criteria are correct and complete for the current HTML schema.** The three detection arms (class `section-label`, class `comment-area`, tag in h1/h2/h3) exactly match the three structural elements produced by `_build_section_html` (label div, h2 with comment button, comment-area div). The spec-mandated format is self-consistent: `_build_section_html` produces exactly what `_is_structural_child` preserves. Tests `test_section_label_preserved_after_replace`, `test_section_heading_preserved_after_replace`, and `test_comment_area_preserved_after_replace` verify all three preservation rules independently.

The h1/h3 arms are forward-compat allowances — `_build_section_html` only produces h2, but the detection handles h1 and h3 for manually-authored sections. Not a defect.

### Flagged area 2: `__copy__()` semantics in `_op_replace_section_content`

The task prompt asked to verify Tag.copy() semantics and whether the fallback silently drops elements.

**Finding: Both the copy path and the fallback are correct.** Verified via live execution:

1. `BeautifulSoup(new_content, "html.parser")` with a fragment like `"<p>Para 1</p><p>Para 2</p>"` produces bare Tag children of the document object — NOT wrapped in `<html><body>`. Python's html.parser does not add wrapper elements for fragment inputs. Iterating `new_soup.children` correctly yields `[<p>Para 1</p>, <p>Para 2</p>]`.

2. `Tag.__copy__()` on a bs4 Tag performs a deep copy including the full subtree. `NavigableString` inherits `__copy__` from str and returns a string copy. The fallback (`else child`) would only fire for objects that are neither — which does not occur in a parsed HTML tree. Verified: the full simulate of `_op_replace_section_content` with multi-paragraph content produces the correct output.

3. For `_op_add_section`: the built section element is inserted via `insert_after` — no `__copy__` call is needed because the element is freshly built from a fresh soup object with no prior tree membership.

**One advisory edge case** (not blocking): when `new_content` contains inline HTML (e.g., `text with <em>emphasis</em>`) but no block-level elements, the plain-text branch fires and calls `p.string = new_content.strip()`, which treats the HTML as literal text and escapes the tags. The docstring says new_content may be "raw HTML or plain text" — the intended usage is block-level HTML or plain text, not inline-only HTML. This is a reasonable design boundary and is documented in the module docstring.

### Flagged area 3: Atomic semantics

File is written via `html_path.write_text(modified, encoding="utf-8")` — not via tmp-rename. As acknowledged in the PR description: "if killed between last instruction and write, edit is lost (not corrupted)." The docstring claim "atomic on success, no partial-write on error" is accurate for the instruction-batch semantics: all instructions run against an in-memory tree, and the file is only touched after all succeed. The remaining risk (interrupted `write_text`) is OS-level and acceptable for this use case. Not a blocker.
