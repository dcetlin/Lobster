## Stage 1 — Vision Alignment

**Prior entering review:** This implementation is solving the wrong problem, or solving the right problem in a direction that forecloses better paths.

**Theory of change:** PR #1262 replaces heuristic keyword scanning ("bug", "fix") in `_select_prescribed_skills()` with structured-field inspection (`reentry_posture` → `register` → `type` → summary fallback).

**Vision alignment:** Confirmed. `vision.yaml principle-3` ("Determinism over judgment for conditionals — If-then logic and field checks are code, not LLM instructions") is the direct anchor. The PR moves from a heuristic string scan to deterministic field checks — exactly what principle-3 prescribes. `vision.yaml constraint-2` is also served: skill selection decisions are now traceable to specific structured fields rather than inferred from conversational texture.

**Scenario in which this is the wrong path:** If `reentry_posture`, `register`, and `type` fields are unset or empty in the majority of production UoWs, the structured path produces no signal and all real-world selections fall through to the summary fallback. In that scenario, the PR changes the code path but not the runtime behavior, and the improvement is cosmetic. This is a deployment concern, not a code correctness issue — and it does not block.

**What would be the cheaper test?** A production query of field-population rates on `reentry_posture`, `register`, `type` across current UoWs would verify the structured path fires meaningfully. Not required for this review; the PR description confirms the fields are populated (the PR references real posture values and registers by name, not hypothetically).

**What does this foreclose?** Nothing of value. Keyword scanning on summary was a known fragile heuristic. Structured-field inspection does not foreclose any valuable direction.

**Encoded Orientation check (OODA constraint-3):** This PR changes how skills are prescribed to agents — a durable behavioral default. Prior logged decision: issue #301 (referenced in PR description as "Closes part of #301"). vision.yaml anchor: `principle-3` directly. Both conditions met. **Passes.**

## Stage 2 — Quality Review

**Does it do what it claims?**

Yes. The inspection order (`reentry_posture` → `register` → `type` → summary fallback) is correctly implemented:

1. `reentry_posture in _DEBUG_POSTURES` → append `systematic-debugging`
2. `reentry_posture in _VERIFY_POSTURES` → append `verification-before-completion`
3. `uow.register == UoWRegister.ITERATIVE_CONVERGENT` → append `systematic-debugging` if not already present
4. `uow.type != UoWType.EXECUTABLE` → early return (skips summary fallback entirely for non-executable UoWs)
5. `if not skills:` summary fallback fires only when steps 1–3 produced nothing

The `if not skills` gate on the summary fallback is the critical behavioral change. It is correctly implemented.

**What would break without the key decisions?**

- Without the `if not skills` gate: summary keywords would fire alongside structured-field results, producing duplicate or spurious skills.
- Without the `uow.type != UoWType.EXECUTABLE` early return: seed/classification UoWs with "bug" or "fix" in their summaries would incorrectly receive `systematic-debugging`.

**What failure modes exist?**

- None surfaced by this review. The logic is simple and the test coverage addresses the boundary cases.
- The `startup_sweep_possibly_complete` posture mapping to `_VERIFY_POSTURES` (and thus `verification-before-completion`) is reasonable — if a startup sweep may have completed, verification is appropriate.

**What patterns does this introduce that will propagate?**

- Module-scope frozensets of enum values as classification gates — a clean, already-established pattern.
- Structured-field-first inspection with summary fallback as last resort — a good template for any future skill-selection expansion.

**What does this make easier / harder for future work?**

- Easier: adding new reentry postures or registers to drive skill selection is a one-line frozenset addition. Adding new summary tokens is also one-line.
- Harder: nothing. The summary fallback is preserved for genuine cases where structured fields are empty.
