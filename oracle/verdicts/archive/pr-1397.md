The root cause is confirmed in the PR description: 5 UoWs with `source_ref = NULL` and truthy `source` values like `"ralph-test"` or `"manual"` caused `get_issue(uow.source)` to pass a non-ref string to `source_ref_from_str()`, which raises `ValueError: not enough values to unpack`. **Could there be a cheaper path?** Considered: could the fix be at the data layer (backfill NULL source_ref rows)? No — the guard exists precisely for UoWs that legitimately have no GitHub issue to track. Clearing source_ref=NULL rows would destroy the intended semantics. The fix is correctly placed at the consumption layer.

**What does this foreclose?** Nothing. The fix is a 1-field name correction in guard conditions and audit writes. It does not change the data model, the state machine, or the tend()/requalify() processing logic beyond stopping the crash.

**Alignment verdict:** Confirmed. The garden caretaker's reliable operation is directly required by vision constraint-4 (minimize metabolic cost) and the success criterion "Dan can ask 'what should I work on?' and receive an answer from a single Registry query anchored to current_focus."
