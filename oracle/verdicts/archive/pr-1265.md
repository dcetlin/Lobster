**Adversarial prior:** This implementation is solving the wrong problem, or solving the right problem in a direction that forecloses better paths.

The theory of change: `claude -p` subprocess calls in scheduled tasks are a reliability liability — they introduce process-level dependencies, create cascading failure modes (subprocess timeout → silent data loss), and add unnecessary latency and cost. Replacing them with direct DB reads and Anthropic SDK calls removes a structural fragility.

The delivery-layer inversion is not a case of label-overpromise, silent non-functional gate, or instruction accumulation. The golden pattern "delivery error handling preserving collected data" is directly applied here.

**Vision alignment:** Confirmed. This work directly serves:
- **constraint-4** (minimize metabolic cost of cybernetic engagement): removing subprocess overhead and fragile delivery paths reduces system friction
- **constraint-1** (no system change that increases fragility or atrophies judgment): this reduces fragility, does not increase it

**Opportunity cost:** Negligible. This is maintenance against a known antipattern with no speculative risk.

**What this forecloses:** Nothing. Direct DB reads are more stable than subprocess calls; the SDK call is a direct replacement with better failure semantics.

**Alignment verdict:** Confirmed.

### Stage 2: Quality Review

**Claim verification:** The PR claims to (1) replace `call_mcp()` with direct `messages.db` SQLite query in weekly-epistemic-retro.py, (2) replace `generate_retro()` subprocess with Anthropic SDK call, and (3) add fallback error handling to deliver functions in all three scripts.

All three claims verified against the diff and against the PR branch directly.

**Implementation findings:**

1. **`fetch_conversation_history()` — direct SQLite read:** Clean implementation. Uses `LOBSTER_MESSAGES` env var for DB path (consistent with rest of codebase), handles missing DB gracefully with a warning + empty return, uses parameterized query, closes connection explicitly. `LIMIT 100` is consistent with previous behavior (the old `call_mcp` used limit=100). The `json.dumps([dict(r) for r in rows], default=str)` serialization is appropriate — `sqlite3.Row` objects are dict-coercible, `default=str` handles any non-JSON-serializable column values.

2. **`generate_retro()` — Anthropic SDK:** `import anthropic` is deferred inside the function (not at module top), which is acceptable for an optional dependency. `client = anthropic.Anthropic()` with no explicit API key means it falls through to `ANTHROPIC_API_KEY` env var — consistent with how the rest of this codebase uses the SDK. Model `claude-opus-4-7` is appropriate for retro generation complexity. `response.content[0].text.strip()` is the standard pattern for non-streaming responses. Exception caught broadly with a print + empty string return — consistent with the original subprocess error handling contract.

3. **Delivery error handling — all three scripts:** Pattern is consistent: `try/except Exception` wrapping the write operations, fallback file write to `logs/<JOB_NAME>-fallback-<timestamp>.txt`, then `raise` to propagate. The `raise` is important — it ensures the caller knows something failed rather than silently continuing. `fallback.parent.mkdir(parents=True, exist_ok=True)` prevents a secondary failure if the logs directory is missing.

4. **`subprocess` import removal:** Verified — `weekly-epistemic-retro.py` no longer imports `subprocess` or `uuid`. `daily-metrics.py` retains `subprocess` for `run_cmd()` which calls `gh`/`git` CLI commands only (data collection, not LLM invocation). `pattern-candidate-sweep.py` has no subprocess import in the PR branch.

5. **Syntax validity:** All three files pass `ast.parse()` cleanly.

**Failure modes:**
- If `ANTHROPIC_API_KEY` is not set in cron environment, `generate_retro()` will raise `anthropic.AuthenticationError`, caught by the broad except, returning empty string. The retro will produce an artifact with no generated content but will not crash. This is acceptable degradation — same or better than the previous subprocess timeout behavior.
- If `messages.db` schema changes (column rename), `fetch_conversation_history()` will raise an exception caught by the except block, returning empty string. Same graceful degradation.

**Patterns introduced:** Direct SQLite reads in scheduled tasks (not new to the codebase generally, but new for retro specifically). This is a positive pattern — it removes an unnecessary indirection layer.

**Encoded Orientation check (constraint-3):** This PR does not change behavioral defaults, system constraints, agent identity, or decision-making rules. It is an implementation improvement, not an Encoded Orientation decision. Constraint-3 does not apply.

**What this makes easier:** Future scheduled tasks that need conversation history can use the same direct DB read pattern rather than subprocess indirection. The fallback pattern is a reusable idiom.

**What this makes harder:** Nothing. The change is strictly a simplification.
