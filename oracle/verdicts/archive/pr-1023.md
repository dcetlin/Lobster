### Stage 2 — Quality Review

**Does it do what it claims?** Yes. The routing pipeline is pure and composable: `compute_pattern_confidence` is a side-effect-free function; `route_pattern_to_action` gates on confidence, checks dedup, and dispatches to isolated side-effect functions. The test suite covers HIGH confidence task creation, HIGH confidence digest flagging, deduplication (second call is no-op), MEDIUM confidence no-action, and monotonically increasing task IDs.

**Key decisions and what would break without them:**
- `INSERT OR IGNORE` on `pattern_event_id` as primary key: without this, re-running the classifier on already-processed events would create duplicate tasks. Idempotency is structurally enforced.
- `LOBSTER_MESSAGES` env var: the path is environmentally configurable, consistent with `LOBSTER_WORKSPACE` handling. Without this, test isolation would require real filesystem manipulation.
- Double-threshold gate (HIGH = events >= threshold * 2): without this doubling, a minimal pattern detection (at threshold) would immediately trigger task creation. The doubling is the confidence margin between detection and action.

**Failure modes:**
- Non-atomic file write: `tasks_path.write_text(...)` is not tmp-rename atomic. A crash mid-write produces a corrupt JSON file. The recovery path (`except Exception: existing = {"tasks": [], "next_id": 1}`) handles this by resetting to empty — data loss from the in-flight write, not a hard crash. Low severity given the recovery path exists and the file is non-critical. The `binary confirm with pending-JSON and ruamel round-trip write` golden pattern recommends tmp-rename; this is a note for future cleanup, not a blocker.
- `compute_pattern_confidence` docstring claims to return "HIGH", "MEDIUM", or "LOW" but the function never returns "LOW". The routing logic gates only on `!= "HIGH"`, so the binary HIGH/MEDIUM is sufficient for correct behavior. Note only — docstring accuracy defect, no behavioral impact.

**Patterns introduced:**
- Threshold-gated action routing as a composable pipeline with isolated side effects at boundaries. Reusable for any future classifier output → action translation.
- `pattern_actions` as a dedup table for classifier-driven side effects. This pattern will propagate to any future action type added to this routing layer.

**What this makes easier:** Adding new action types requires only (a) adding the pattern to the appropriate set (`_TASK_PATTERNS`, `_DIGEST_PATTERNS`, or a new set) and (b) adding a handler branch in `route_pattern_to_action`. The architecture is open to extension without modifying existing paths.

**What this makes harder:** Nothing material. The digest_flag consumption by nightly-consolidation is not yet wired end-to-end; the decision record acknowledges this as a deferred connection, not a foreclosed direction.
