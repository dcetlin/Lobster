## Round 1 Required Changes — Status

All four required changes are addressed in commit db73e42d.

**1. lastIndex bug (blocking in R1)** — FIXED.
`re.test()` guard removed. Replacement is now detected via `newHtml !== html` sentinel. The sentinel correctly handles all edge cases: no match (strings equal, no update), match found (strings differ, html updated), empty string (no term match possible). ✓

**2. `def` variable unused / backreference vulnerability (medium in R1)** — FIXED.
`def` now includes full HTML escaping (`&`, `<`, `>`, `"`) and `$` backreference escaping via `.replace(/\$/g, '$$$$')`. This is the correct two-level escape: each `$` in the definition becomes `$$` in `def` (step 1), which collapses to `$` when `def` is used as a replacement string in `html.replace(re, ...)` (step 2). The concern in the R1 prompt that `$$$$` was wrong was incorrect — `$$$$` is the right value for this two-step escaping pattern. `def` is now used in the replacement string instead of raw `vocab[term]`. ✓

**3. Misleading "whole word only" comment (medium in R1)** — FIXED.
Comment now reads "Match case-sensitive (no word-boundary anchors — terms may appear mid-word)." Accurately describes the implementation. ✓

**4. CSS source-order conflict for `.section h3` (medium in R1)** — FIXED.
`_build_global_css` now emits the canonical h3 rule with `font-weight: 700`, `margin: 32px 0 6px`, `padding-bottom: 6px`, `border-bottom: 1px solid var(--border)`, and a `:first-of-type` override. `_SECTION_CONTENT_CSS` no longer contains a `.section h3` rule — it retains only `hr`, `.section ul li`, and `.section p + ul` rules, which are genuinely distinct concerns from the h3 typographic hierarchy. Single authoritative rule; no source-order arbitration. ✓
