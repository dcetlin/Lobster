## Findings

**Failing check — stale test assertion (CI will fail):**

`tests/unit/test_orchestration/test_adaptive_steward.py`, line 819–820:

```python
def test_haiku_model_id(self) -> None:
    """HAIKU_MODEL must use the claude-haiku-4-5-20251001 model."""
    assert HAIKU_MODEL == "claude-haiku-4-5-20251001"
```

The PR changes `HAIKU_MODEL` from the string literal `"claude-haiku-4-5-20251001"` to `os.environ.get("LOBSTER_HAIKU_MODEL", "claude-haiku-4-5")`. Because `LOBSTER_HAIKU_MODEL` is not set in the CI environment, `HAIKU_MODEL` evaluates to `"claude-haiku-4-5"` at module import time. The test assertion will fail with:

```
AssertionError: assert "claude-haiku-4-5" == "claude-haiku-4-5-20251001"
```

This is the learnings.md 2026-04-22 (#827) stale-test-assertion pattern: the PR removes a behavior (pinned dated model alias) that an existing test explicitly asserts. The test's failure is confirmation the change is correct — but merging with it intact inherits a known CI failure.

**Resolution:** Update the test to assert the new default: `assert HAIKU_MODEL == "claude-haiku-4-5"`. Alternatively, invert the assertion to verify the dated pin is no longer used: `assert "20251001" not in HAIKU_MODEL`.

## Stage 2: Quality review

**Mode: VERIFICATION** — external adjudicator is the test suite.

### What the PR does

1. Replaces the `anthropic.Anthropic()` SDK production path with a `claude -p` subprocess call using `_build_claude_env()` from `steward.py`.
2. Preserves the `anthropic_client` injection path for tests — routing: `if anthropic_client is not None` → legacy SDK path; else → subprocess path.
3. Changes `HAIKU_MODEL` from a pinned dated alias (`claude-haiku-4-5-20251001`) to a durable alias (`claude-haiku-4-5`) with `LOBSTER_HAIKU_MODEL` env override.
4. Adds `_NORMALIZATION_TIMEOUT_SECS = 30` for bounded subprocess calls.
5. Adds explicit error handling for timeout, non-zero returncode, and empty stdout.

### What would break without the key decisions

- Without the function-body `from orchestration.steward import _build_claude_env`: module-scope import would create a circular dependency risk (verdict_normalization → steward → anything that imports verdict_normalization). The function-body import is the established pattern in this codebase (learnings.md #974, #1220 — function-body local import for cross-module imports that create circular dependencies).
- Without the `anthropic_client is not None` branch inversion: existing tests would fail immediately with no injection path available for the subprocess-free test environment.
- Without `_NORMALIZATION_TIMEOUT_SECS`: subprocess would block indefinitely if claude hangs, stalling UoW closure.

### Findings

**Finding 1 (CI failure — NEEDS_CHANGES):** `test_haiku_model_id` asserts `HAIKU_MODEL == "claude-haiku-4-5-20251001"`. The PR changes the default to `"claude-haiku-4-5"`. Test fails in CI. Learnings.md 2026-04-22 (#827): "A test that asserts behavior an oracle decision explicitly prohibits becomes a stale assertion after the fix lands." Apply: this test asserts the dated pin that the PR explicitly removes. The fix is one line: update the expected value.

**Finding 2 (note — no CI failure):** The production subprocess path (`anthropic_client is None`) has zero test coverage. The PR's CI tests exercise only the legacy injection path. This is a known structural limitation (no live claude subprocess in CI) and the PR design acknowledges it by preserving the injection path. The subprocess error paths (timeout, non-zero returncode, empty stdout) are untested in CI. This is a design trade-off, not a defect — but it means the post-deploy verification step in the PR test plan is load-bearing. The PR test plan correctly marks this as a manual deployment check.

**Finding 3 (note — no CI failure):** `HAIKU_MODEL` is now computed at module import time from `os.environ.get(...)`. A test that calls `monkeypatch.setenv("LOBSTER_HAIKU_MODEL", ...)` and then uses `normalize_hypothesis_text` without the injection path would silently test the wrong constant (the learnings.md #839 pattern). The current tests do not exercise this scenario — they all pass `anthropic_client=mock_client` which routes through the legacy path and uses the module-scope constant consistently. No test regression here, but future tests for the subprocess path should be aware of this.

**Finding 4 (note — module docstring stale):** The module-level docstring at line 18 still references the cached-prompt note ("Prompt caching: the system prompt is marked with cache_control...") — but this has been updated in the PR diff itself. Confirmed by reading the branch version: the docstring is correctly updated to "LLM dispatch: uses `claude -p` subprocess via _build_claude_env()...". No issue.

I specifically checked for tests asserting the removed dated model alias after seeing the HAIKU_MODEL constant change, weighted this as a CI-blocking finding (not advisory), and did not treat it as a minor style note.
