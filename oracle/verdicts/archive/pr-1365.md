## Stage 2: Quality Review

**Mode: VERIFICATION.** External adjudicator: pytest test suite (343 tests, all pass on the PR branch). The oracle's role is to name the violation if one exists.

### 1. Multiple occurrences of the same term in one text node

The `replace()` callback fires once per match of the regex. With the `/g` flag and a function replacer, JavaScript's `String.replace` calls the function once per match. Each call appends to `defns[]` independently, producing unique placeholder tokens (`__TTIP_0__`, `__TTIP_1__`, `__TTIP_2__` for three occurrences of the same term). The restore loop iterates `defns.length` and replaces each unique placeholder. All three occurrences get their own tooltip span with the correct captured text.

**Result: correct. The split/join restore handles multiple occurrences correctly.**

### 2. Dollar-sign escape removal

The old code used string-form replacement (`html.replace(re, '<span>...$1</span>')`) where `$1` is the capture group backreference and `$` in the definition text needed escaping to `$$$$`. The new code uses a function replacer (`html.replace(re, function(match, captured) {...})`) — JavaScript function replacers do not interpret backreferences in the return value. The return value is used literally as `'__TTIP_' + idx + '__'`.

Pass 2 uses `html.split('__TTIP_' + i + '__').join(defns[i])`. `Array.join` and `String.split` perform literal substitution with no backreference interpretation. Definition text containing `$` passes through correctly.

**Verified:** `vocab_tooltip.render({'vocab': {'Price': 'Costs $100 per unit.'}})` produces `Costs $100 per unit.` in the embedded JSON unchanged.

**Result: correct. Dollar-sign escape removal is safe and correct.**

### 3. Placeholder token partially matching a term regex — THEORETICAL EDGE CASE, ACCEPTABLE IN CONTEXT

The placeholder token format is `__TTIP_N__`. The substring `TTIP` appears in every placeholder token. If a vocabulary term has `TTIP` as a substring (e.g., the term literally named "TTIP"), and that term is processed *after* another term (so an `__TTIP_0__` placeholder already exists in the working string), the TTIP regex will match both the intended occurrence in the original text AND the `TTIP` inside `__TTIP_0__`. This creates a corrupted placeholder: the inner TTIP occurrence gets a new placeholder index, producing `____TTIP_1___0__` instead of `__TTIP_0__`, and the restore loop cannot find `__TTIP_0__` anymore.

**Severity assessment:** This is a valid correctness defect, but in the practical use context it is near-zero-probability:

- The component is a vocab glossary for educational/music content.
- The token prefix `__TTIP_` was chosen to be unlikely to appear in natural language vocabulary.
- The only trigger is a term whose text appears as a substring of `__TTIP_N__` — that is, terms containing the exact string `TTIP` (all uppercase).
- `TTIP` (Trans-Pacific Partnership trade agreement) is the only common-language entity with this exact form. Musical, anatomical, or technical glossary terms do not use this abbreviation.

The existing test suite does not cover this edge case, but the practical exposure is confined to vocabularies containing the acronym `TTIP` or similar. This does not block APPROVED given the domain specificity.

**Result: theoretical defect with near-zero practical exposure in the intended domain. Not a NEEDS_CHANGES blocker.**
