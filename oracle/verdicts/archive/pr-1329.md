## Round 1 — 2026-05-26

### Stage 1: Vision Alignment

**Prior check:** Learnings.md — no matching failure pattern for "hook call path swallowing exceptions incorrectly." Golden patterns — "crash-safe two-step delivery" and "internal vs. user-facing task" are consistent with this PR's design (the fail path is purely internal, never surfaces to user).

**Mode:** VERIFICATION — the implementation has an external adjudicator (test suite). The tests are behavioral contracts; the oracle's role is to confirm coverage completeness and structural correctness.

**Theory of change in vision.yaml:** The system should extend cognitive reach without requiring screen presence (constraint-4: minimize metabolic cost). A 10–600 minute lag on orphan UoW state recovery is a direct metabolic cost: stale executing-status UoWs accumulate, the steward cannot act on them until TTL sweep reclassifies them, and recovery is deferred.

**Assumption required for this work to be right:** The SubagentStop hook's MAX_HOOK_FIRES exhaustion path is a reliable signal that the UoW is genuinely orphaned. If the hook misfires (false positive), this transition could fail a UoW that was actually in-progress. The guard (`uow.status != UoWStatus.EXECUTING`) ensures idempotency, and the existing MAX_HOOK_FIRES threshold (5 retries) makes false positives unlikely in practice.

**Opportunity cost check:** Minimal — this is a targeted fix to an existing hook exit path, not a new system. The diff is 176 lines (12 in the hook, 72 in wos_completion.py, 92 in tests). No new infrastructure introduced.

**What this forecloses:** Nothing. The TTL orphan sweep remains as a fallback for any case where the hook fails to fire. This adds an explicit early-failure path without removing the recovery path.

**Alignment verdict:** Confirmed — directly reduces metabolic cost of UoW lifecycle management, consistent with constraint-4 and the steward's ability to act without polling delay.
