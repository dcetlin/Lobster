## Round 1 — [2026-05-23]

## Stage 1 — Vision Alignment

**Prior entering review:** This implementation is solving the wrong problem, or solving the right problem in a direction that forecloses better paths.

**Finding (written before seeing implementation):**

The PR title is "refactor(docs): reorganize docs/ by epistemic status and use-case." The stated theory of change is structural: docs organized by origin (where created) rather than epistemic status (what authority the file carries) means an agent loading `docs/wos-v3-proposal.md` alongside `docs/wos-constitution.md` gets no structural signal that one is superseded and the other is authoritative. Directory position as epistemic signal is a real idea: the form of the repository should answer orientation questions without requiring the reader to know the history.

What would have to be true for this to be wrong: either (a) agents and humans do not select docs by directory browse — they are loaded by name from instructions or code references, in which case the directory restructure has no effect on agent orientation, or (b) the reorganization is correct in theory but breaks existing load paths without providing a migration, compounding disorientation rather than reducing it.

Signal (a) is partially addressed by the PR description, which explicitly names two broken references: `.claude/agents/review.md` (blocked due to write permissions) and `src/orchestration/` (explicitly deferred per PR's own boundary constraint). Both are live agent orientation paths. The PR acknowledges these breaks but does not fix them. This is the "path fix completeness" failure mode from learnings.md PR #796: when fixing a path inconsistency, enumerate all path-reference forms — not just the one observed in the failing case.

Signal (b) is the more concerning scenario: the PR ships a docs restructure with known dangling references in agent-loading paths, and defers those fixes, potentially creating a window where agents load stale or absent docs.

The vision alignment question is not whether reorganizing by epistemic status is a good idea (it is). The question is whether shipping it with known broken agent orientation paths serves the vision's fundamental intent: agents that can make intent-anchored decisions. A reorganization that breaks current agent orientation to improve future orientation is a regression in the short term.

**The more consequential concern:** The PR title says "refactor(docs)" but the diff contains: (1) a 327-line new document `docs/wos-observability-gap-analysis.md` at the docs root (not moved, newly introduced, outside the stated directory skeleton), (2) a new `failure-breakdown` CLI command in `src/orchestration/registry_cli.py` with ~170 lines of production code, (3) a behavioral change to `src/orchestration/steward.py` (upstream-repo write guard in `_llm_prescribe`), (4) ~218 lines of new tests in `test_registry_cli.py`, and (5) three new oracle verdict files for PRs 1029, 1030, 1031. The PR is titled and described as a docs reorganization, but it bundles three distinct workstreams: docs structure, a new CLI feature, and a production behavioral guard. This is the feature-bundling failure mode from learnings.md (2026-05-14 #1148 and 2026-04-08 #717).

**What this work forecloses:** Nothing fundamental. All pieces are directionally correct. But the bundling means a NEEDS_CHANGES on the docs path forces re-review of correct code changes, and a structural defect in any one layer blocks approval of the others.

**Alignment verdict: Questioned.** The docs reorganization serves the vision (epistemic clarity for agents), but the PR as submitted mixes three workstreams, ships with known broken agent-loading paths, and introduces a new observability document at the root that does not fit the reorganization's own taxonomy.

**Stage 1 finding is locked.**
