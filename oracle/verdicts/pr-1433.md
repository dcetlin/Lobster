## Required changes

**Finding 1 — Mirror constant `EXPECTED_LARGE_FIELDS` in test file (learnings.md pattern, 7 recurrences)**
`tests/unit/test_orchestration/test_prescribe_artifacts.py` line 358–364 declares `EXPECTED_LARGE_FIELDS = frozenset({...})` with values identical to production `LARGE_FIELDS`. The test assertion `assert LARGE_FIELDS == EXPECTED_LARGE_FIELDS` does produce a loud failure on divergence (which distinguishes this from the silent-mirror form in learnings.md), but the pattern is: when a new constant is introduced in production and a test is written for it in the same PR, the test must import the constant rather than re-declare it. The correct form is `assert LARGE_FIELDS == {"issue_body", "steward_log", "dan_register", "vision_orientation", "diagnosis_section"}` with an inline literal (one-time declaration, readable without tracing) or — better — remove `EXPECTED_LARGE_FIELDS` entirely and assert using `frozenset({"issue_body", ...})` inline. The current form creates a local mirror constant that will diverge silently when `LARGE_FIELDS` changes and the test author forgets to update `EXPECTED_LARGE_FIELDS`. Severity: same-PR mirror-constant is the PR #1408 variant per learnings.md 2026-06-03.

**Finding 2 — Test isolation: verify `handle_wos_prescribe` tests do not write to real artifact directory**
The task prompt reports that the dispatcher's live inbox was flooded with `uow_test_*` and `uow_lt_*` wos_prescribe messages during this PR's test run. The PR's tests in `test_prescribe_artifacts.py` are correctly isolated: all `_write_prescription_request` calls use `monkeypatch.setattr(steward_mod, "_INBOX_DIR_PATH", tmp_path/"inbox")` and pass `prescribe_artifact_dir=artifact_dir` pointing to `tmp_path`. However, `TestHandleWosPrescribeArtifactPath._make_msg_with_artifact` calls `write_prescribe_artifact(uow_id, artifact_dir=artifact_dir, ...)` where `artifact_dir` is the `tmp_path` fixture — this is correctly isolated. The `TestHandleWosPrescribeBackwardCompat` tests do NOT call `write_prescribe_artifact` at all — they construct message dicts directly. **The inbox flooding is NOT caused by this PR's test file.**

However: the test `TestHandleWosPrescribeArtifactPath` calls `handle_wos_prescribe(msg)` without monkeypatching `PRESCRIBE_ARTIFACTS_DIR`. The `handle_wos_prescribe` function calls `read_prescribe_artifact(artifact_path)` which resolves the path passed in `msg["artifact_path"]`. Since `artifact_path` is constructed from `write_prescribe_artifact(uow_id, artifact_dir=tmp_path, ...)`, the path points to `tmp_path` — not the real workspace. **No real-dir writes occur in these tests.** The flooding was caused by a pre-existing test or by a different execution path not in this PR's diff. This finding does not block approval but must be explicitly stated in the verdict so the inbox flooding is not attributed to this PR.

**Resolution contract:**
- Gap 1 (mirror constant): Remove `EXPECTED_LARGE_FIELDS` local declaration. Replace `assert LARGE_FIELDS == EXPECTED_LARGE_FIELDS` with `assert LARGE_FIELDS == frozenset({"issue_body", "steward_log", "dan_register", "vision_orientation", "diagnosis_section"})` inline, or keep `EXPECTED_LARGE_FIELDS` but add a comment explicitly naming it as a local mirror with a divergence risk — this second option is not preferred. The mirror-constant pattern (7 recurrences in learnings.md) is a required first-pass oracle check. The assertion is load-bearing but its form is incorrect.

## Stage 2 — Quality review

### Root cause fix verification (the crux question)

**Does moving fields to a sidecar actually remove the blocking inference from the dispatcher?**

Yes. The pre-PR handler called `claude -p` (LLM inference) synchronously during `handle_wos_prescribe`. The post-PR handler:
1. Calls `read_prescribe_artifact(artifact_path)` — Python file I/O, ~1ms.
2. Assigns fields to local Python variables.
3. Assembles a prompt string — Python string ops, ~1ms.
4. Returns `{"action": "spawn_subagent", "prompt": <string>}`.
5. Dispatcher calls `Task(run_in_background=True, prompt=...)`.

The LLM inference for the prescription now runs in the background subagent, not in the dispatcher's blocking call. The dispatcher's Python loop processes this message in under a second. **Root cause is fixed.**

**Residual context accumulation:** The full prompt content (up to ~10KB post-truncation, since `issue_body` is truncated at 2000 chars) does appear in the dispatcher's context via the `Task` tool call argument. This is an accepted trade-off: the context grows per prescription, but this is not the failure mode that caused restarts.

### Backward-compat fallback

`handle_wos_prescribe` logic:
```python
artifact: dict | None = None
artifact_path: str = msg.get("artifact_path", "")
if artifact_path:
    artifact = read_prescribe_artifact(artifact_path)

if artifact is not None:
    # new path: use artifact fields
else:
    # old path: use inline fields
```

Three cases:
1. `artifact_path` present, file exists → artifact used. Correct.
2. `artifact_path` present, file missing → `read_prescribe_artifact` returns `None` → `artifact is None` → inline fallback. Correct. (Tested by `test_missing_artifact_file_falls_back_to_inline`.)
3. `artifact_path` absent → `msg.get("artifact_path", "")` returns `""` → falsy → skip read → `artifact is None` → inline fallback. Correct. (Tested by `TestHandleWosPrescribeBackwardCompat`.)

The `None` sentinel from `read_prescribe_artifact` is correctly handled — no crash on missing file. The fallback path is exercised by tests.

### `diagnosis_section` handling

`diagnosis_section` is in `LARGE_FIELDS` and is written to the artifact by `write_prescribe_artifact`. It is NOT extracted from the artifact in `handle_wos_prescribe` (neither is it extracted from inline fields — this was the case pre-PR too). The field was included in the old inline message but never consumed by the handler. The PR correctly removes it from the inline message and puts it in the artifact. No behavioral regression. Future extraction from the artifact is possible without a message format change.

### Module-level constant isolation (`PRESCRIBE_ARTIFACTS_DIR`)

Computed at import time from `os.environ.get("LOBSTER_WORKSPACE", ...)`. Per learnings.md (2026-04-22, #839), `monkeypatch.setenv` would not affect this constant. The PR avoids this trap by providing an `artifact_dir` parameter on both `write_prescribe_artifact` and `read_prescribe_artifact`, and `prescribe_artifact_dir` on `_write_prescription_request`. Tests pass explicit `tmp_path` overrides. The design is correct.

### Filename uniqueness / collision

`{uow_id}.prescribe.json` is the filename. Since `uow_id` is unique per UoW, no cross-UoW collision. Re-prescription of the same UoW (retry) overwrites the existing artifact (idempotent, tested). Correct.

### `prescribe_artifact_dir` kwarg keyword-only enforcement

The `*` separator in `_write_prescription_request` signature makes `prescribe_artifact_dir` keyword-only. The single production call site does not pass this parameter (uses the default `None` → `PRESCRIBE_ARTIFACTS_DIR`). No positional argument collision risk.

### TTL / cleanup

Acknowledged as deferred in the PR description. Artifact files accumulate per UoW per attempt. For the current execution cadence (WOS paused), unbounded growth is not an immediate risk. Acceptable as a follow-up item.

### Mirror constant (learnings.md first-pass check)

`EXPECTED_LARGE_FIELDS` in the test file re-declares `LARGE_FIELDS` with identical values. This is the PR #1408 pattern (same-PR mirror for a new constant in an existing module). The assertion `LARGE_FIELDS == EXPECTED_LARGE_FIELDS` does provide loud failure on divergence, so severity is lower than silent mirrors. But the pattern is a required NEEDS_CHANGES per learnings.md 7-recurrence history.

### Test isolation verdict

Tests in this PR are correctly isolated:
- All steward path tests monkeypatch `_INBOX_DIR_PATH` to `tmp_path`.
- All artifact writes pass `artifact_dir=tmp_path`.
- `handle_wos_prescribe` tests pass artifact paths pointing to `tmp_path`.
- No test invokes the real inbox write path or the real `PRESCRIBE_ARTIFACTS_DIR`.

The inbox flooding reported during this PR's test run is not caused by tests in this diff. Investigation should focus on pre-existing steward test files that may invoke `_write_prescription_request` without the new `prescribe_artifact_dir` kwarg — those tests would now write artifacts to the real `PRESCRIBE_ARTIFACTS_DIR`. Specifically: `tests/unit/test_orchestration/test_wos_prescribe.py` existed before this PR. The PR updates it (monkeypatching + `prescribe_artifact_dir=artifact_dir`), but a test run using the old test file against the new production code would write to the real artifacts directory. The updated test file in this PR diff correctly adds `prescribe_artifact_dir=artifact_dir` to all calls.

### Patterns introduced

The `prescribe_artifact_dir` injectable parameter pattern follows the golden-patterns.md `caller-declared identity` principle — each caller declares its working directory rather than relying on the global constant. This is correctly structured.
