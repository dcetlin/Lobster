### Implementation correctness

**Mechanism 1 (registry.py _upsert_typed):**
- The `vision_ref_missing` audit INSERT is inside the `try:` block, before `conn.commit()`, after the `UoW INSERT`.
- The `except: conn.rollback()` block catches failures of either INSERT and rolls both back together.
- Transaction correctness: verified. If the audit INSERT fails (e.g., DB locked), the UoW is not created — atomicity is maintained.
- The audit entry fires unconditionally on every new UoW creation. This is correct by design: `vision_ref` is never available at upsert time (sweeper sets it later). This is documented in the code comment and PR description.
- Minor observation: the test `test_vision_ref_missing_not_written_when_vision_ref_present` tests that post-sweeper state does not generate additional `vision_ref_missing` entries. This is a correct boundary test even though the creation path always fires the entry.

**Mechanism 2 (steward.py _process_uow Step 2b):**
- `_cycle_anchor_entry` is built as an immutable dict with all required fields.
- `_append_steward_log_entry` overwrites `entry["timestamp"]` with a fresh `_now_iso()`. This is consistent with the function's behavior for all other callers — the initial `"timestamp": _now_iso()` set in the dict is redundant but harmless. All tests pass against this behavior.
- `_write_steward_fields` is called immediately after the vision anchor entry, before Step 3. This follows the crash-safe eager-write pattern used throughout `_process_uow` (lines 4980, 5025, 5052, 5085, etc.). Not a deviation.
