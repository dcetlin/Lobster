### Blocking Issue

The test file already exists on `origin/main` (added by PR #1061, commit `b07fd0b5`). Merging this PR would overwrite the current main version with this branch's variant. The practical difference:

- Main version: shorter, less descriptive test method names (`test_returns_send_reply_action`, `test_text_matches_input`, etc.); 232 lines; uses `monkeypatch` for exception test.
- PR version: more descriptive test method names (`test_stale_open_returns_send_reply_action`, `test_stale_open_text_matches_input`, etc.); 288 lines; uses context-manager `patch` for exception test.

Neither version is wrong. The PR version is actually slightly preferable (more descriptive names, no `monkeypatch` injection in exception test). However, the correct action is **not to merge this PR as-is**, because:

1. The PR description says "No existing files modified" and frames this as a pure addition. Merging would silently modify an existing file on main with no documentation of that fact.
2. The UoW is already marked `DONE`. The artifact field on the UoW points to `dcetlin/Lobster#1061`, not `#1062`. This PR is a redundant artifact for a closed UoW.

**Resolution path:** If the PR version's longer test method names are preferred over the main version's shorter names, the correct action is to either: (a) close this PR as superseded and open a follow-on naming improvement PR with a description that accurately states "renames test methods for clarity, improves exception test to use context-manager patch instead of monkeypatch" — or (b) update this PR's description to accurately state it is renaming existing tests, then proceed to review. Option (a) is preferred because this PR's branch is stale (diverged from main before the file was added).
