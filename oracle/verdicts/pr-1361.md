## Specific gap

**Gap 1: Dispatcher gate placement is not discoverable in normal dispatch flow.**

The HTML document complexity gate was placed as a subsection at the end of `## Working on GitHub Issues`, after `/re-review command`, immediately before the `---` separator preceding `## Agent Council`. This section is semantically scoped to GitHub PR and issue workflows (engineer → reviewer → user, design reviews, /re-review). A dispatcher receiving a request to produce a complex HTML document would not route through `## Working on GitHub Issues`. The natural dispatcher path is `## Task System → When user gives a task` (generalist dispatch) or a command match — neither of which leads through the GitHub Issues section. The failure that motivated this PR (Sensibility Stack v3 session) was a generalist dispatch, not a GitHub issue task. A gate placed only where it will be read by a dispatcher already in the GitHub workflow cannot prevent the failure it was written to address.

**Correct placement:** The gate should be placed either in `## Task System → When user gives a task` (where all generalist dispatches originate) or as a top-level section accessible before task dispatch decisions. The Tier-1 Gate Register in CLAUDE.md, or the Dispatch template gate row's supplemental guidance, are also viable anchors — the criterion being that the gate is encountered in the normal dispatch decision path, not only when a dispatcher happens to be reading the GitHub issues section.
