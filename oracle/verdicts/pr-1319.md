## Advisory findings (not blocking)

### Non-atomic file writes

Both `_PENDING_PROPOSALS_PATH.write_text()` and `_ROUTING_PREFS_PATH.write_text()` use direct `Path.write_text()` instead of atomic tmp-rename. The golden pattern from PR #834 ("binary confirm with pending-JSON and ruamel round-trip write") calls for "atomic via tmp-rename." A crash mid-write could leave partial content. Severity is low because `load_routing_preferences` falls back to `[]` on malformed YAML, but the pattern divergence is worth noting for future consistency.

### UTC time-range matching in condition strings

`match_routing_preference` uses `datetime.now(timezone.utc)` for time-range comparisons. Condition strings like "brain-dump messages arriving between 06:00-09:00" will be interpreted as UTC, not the user's local time (Pacific). Since `maybe_annotate_routing_hint` is not yet wired into the dispatch loop, this is not immediately consequential, but the semantic mismatch should be resolved before the wiring step.

### Comment block reduction on YAML write

The existing `routing-preferences.yaml` has a 15-line comment header including a Schema example. The PR's write logic hardcodes 3 comment lines before `yaml.dump()` output, dropping the schema documentation. Unlike vision.yaml (where ruamel.yaml is used to preserve governance comments), this is documentation-only — not blocking, but the Schema example serves as inline documentation for manual editing.

## Stage 2: Quality review

**What it does well:**
- Clean callback handler pattern following the established `route_callback_message` structure
- Pure functions in `preferences.py` with explicit path injection — testable and stateless
- Module-level cache with named reload function avoids threading state through call chains
- Error handling returns user-readable strings, never raises
- `maybe_annotate_routing_hint` creates a copy of the message dict, preserving immutability of the input
- Tests use `patch` on module-level path constants — the correct pattern per learnings.md #839

**What would break without key decisions:**
- Without `CALLBACK_DATA_HANDLERS` frozenset inclusion, the buttons remain dead
- Without `reload_routing_preferences()` after confirm, new rules wouldn't take effect until the cache reload interval
- Without the `raw.pop("preferences", None)` normalization, the file could accumulate both key spellings

**Failure modes:**
- Concurrent button presses could race on `pending-routing-proposals.json` (low probability, low consequence)
- `_condition_matches` source_hit logic is asymmetric: source is checked in time-range path but not in keyword-only path
- Synthetic fallback in `scan_pattern_observations` returns the most recent event of any type, not necessarily a pattern_observation — could produce irrelevant proposals
