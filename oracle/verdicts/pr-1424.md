## Stage 1: Vision Alignment

**Alignment verdict: Confirmed**

The task addresses a measured operational problem: 8% of heat outcomes trace to merge-pr UoWs retrying already-merged PRs. The current focus in vision.yaml is "clearing WOS open threads" — this directly serves that goal. The WOS executor is currently paused; this check will prevent wasted cycles when it resumes.

**Theory of change:** The WOS executor dispatches based on queue state. Adding pre-flight checks that verify external state (is the PR still open?) before spawning subagents is a structural prevention pattern (principle-1: proactive resilience over reactive recovery). The existing `is_still_needed` framework (PR #1396) was built specifically to host checks like this — this PR is the natural first consumer.

**What this forecloses:** Very little. The key derivation from `source_ref` rather than `uow.type` introduces a minor new concept (semantic sub-types), but it's localized to one function and doesn't modify the extension point contract. If many sub-types accumulate, `_derive_preflight_key` could become a routing layer — worth watching but not a concern for one consumer.

**Opportunity cost:** Low. Well-scoped operational hygiene that aligns with the current focus. Not competing with Stage 1/2 substrate work.

## Stage 2: Quality Review

**Implementation correctness:**
- `_derive_preflight_key(uow)` correctly maps `source_ref.startswith("github:pr/")` to key `"merge-pr"`, all other UoWs to `str(uow.type)`. Backward-compatible.
- `_check_merge_pr(uow)` correctly extracts PR number, calls `gh pr view`, returns False only for `state == "MERGED"`. All error paths (parse failure, gh exit non-zero, exception, timeout) return True (fail-open). This is the correct behavior — the executor must proceed unless explicitly told the work is not needed.
- `is_still_needed` updated to use `_derive_preflight_key` instead of raw `uow.type`. Warning log updated to use `key=` reflecting the indirection. Clean.
- Module-level `import subprocess as _subprocess` enables deterministic monkeypatching in tests. Correct.
- Registration at module load time via `register_preflight_check("merge-pr", _check_merge_pr)` — no executor wiring changes needed. Clean.

**Test coverage:**
- 8 new tests covering all important paths: MERGED (False), OPEN (True), CLOSED (True), gh failure (True), gh exception/timeout (True), non-PR source_ref (True, no gh call), key derivation for PR source, key derivation for non-PR source.
- Monkeypatching targets `orchestration.wos_preflight._subprocess.run` — correct target for the module-level import.
