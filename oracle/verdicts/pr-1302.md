## Stage 1: Vision alignment

**Pre-implementation finding (held through Stage 2 without modification):**

The adversarial prior: this implementation is solving the wrong problem, or solving the right problem in a direction that forecloses better paths.

The theory of change: oracle verdicts — especially for design doc reviews — have been systematically underspecified in their NEEDS_CHANGES content. A vague NEEDS_CHANGES verdict on a design doc is indistinguishable from a vague NEEDS_CHANGES verdict on code, but the epistemic situation is structurally different: code has an external adjudicator (tests, linter), design docs do not. By making this distinction explicit and mandatory before Stage 1 runs, the oracle gains a decision-procedural discriminator that constrains what counts as a legitimate verdict finding in each mode.

**Vision anchor:** principle-5 ("Discriminator improvement over rule addition — when a behavioral rule isn't followed, improve the discriminator"). Mode detection is a discriminator improvement to the oracle's review mechanism, not a new rule layered on top of existing rules. This is the exact application principle-5 names.

**Adversarial scrutiny:**

Does this foreclose better paths? The PR adds a classification step before Stage 1. If the mode classification is wrong — e.g., oracle classifies a hybrid artifact (a doc that also controls behavior) as VALIDATION when VERIFICATION applies — the wrong Stage 2 protocol runs. However, the classification criteria are well-defined (presence or absence of an external adjudicator), and most artifacts in this system fall clearly into one mode or the other. The risk of misclassification is low for the common cases, and the upside (forcing verdicts to cite specific external checks for code PRs, or specific attending observations for doc reviews) is structurally real.

Does this solve the wrong problem? The oracle's underspecification problem on design doc reviews is a real deficit documented in the oracle's existing document-review invocation mode. The Mode Detection section formalizes what was implicit in that mode. The adversarial prior finds no purchase: the problem is correctly identified and the intervention is correctly targeted.

**Alignment verdict:** Confirmed.

**What was not said (held to learnings.md standard for validation-mode reviews):** The Stage 1 prior asks whether a cheaper test of the underlying assumption exists. For this PR, the assumption is that oracle verdicts are underspecified for design docs in ways that mode detection would prevent. A cheaper test would be: examine the last 10 design doc reviews in oracle/verdicts/ and check whether their NEEDS_CHANGES items (if any) are specific attending observations or generic quality complaints. That test was not run here, but the existing "Document review" invocation mode in lobster-oracle.md already contains the "Named gaps" structure that was intended to prevent underspecification — the gap is that it was invocation-mode-specific and not a mandatory classification. The design doc's own structural analysis validates the premise.
