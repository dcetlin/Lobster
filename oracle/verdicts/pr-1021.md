## Stage 1 — Vision Alignment

**Prior entering this review:** This implementation is solving the wrong problem, or solving the right problem in a direction that forecloses better paths.

**Theory of change:** Subagent dispatches lack the `Minimum viable output` and `Boundary` fields required by the Dispatch template gate. The fix relabels the gate's enforcement column from "Advisory" to "Structural" in two instruction documents and adds a Result Elegance Audit block to the dispatcher bootup.

**What would have to be true for this to be the right path:** (1) The Dispatch template gate is currently advisory — i.e., not mechanically enforced. (2) Relabeling the enforcement column in documentation produces meaningfully different dispatcher behavior. (3) Adding a soft-gate audit block before relay addresses the output-volume problem structurally.

**Stage 1 finding — this PR relabels documentation for a gate that is already structurally enforced:**

`hooks/dispatch-template-check.py` already exists (introduced in PR #825 per golden-patterns.md advisory-to-hook promotion pattern, 2026-04-22). That hook intercepts every Agent tool call from the dispatcher and exits with code 2 (hard block) if either `Minimum viable output:` or `Boundary:` is absent from the prompt. The hook fires regardless of context state, instruction absorption, or session length. The Dispatch template gate is already structurally enforced at the hook layer.

The golden-patterns.md advisory-to-hook promotion pattern (2026-04-22) states this precisely: "A PreToolUse hook fires regardless of context state; the check is mechanical, not memory-dependent." The CLAUDE.md enforcement column currently says "Advisory" — which is inaccurate, not weak. The gate was promoted to structural by the hook, not by the CLAUDE.md label. This PR corrects the label's accuracy without changing the enforcement reality.

**What this means for the Stage 1 question:** The PR is not solving the wrong problem. The label correction is accurate and appropriate — the hook is structural; the documentation should say so. The Stage 1 concern is not about misalignment; it is that the PR's framing ("structural enforcement") suggests it is introducing enforcement, when the enforcement already exists. The risk is that this framing forecloses recognition that the enforcement layer (the hook) and the documentation layer are different systems with different failure modes.

**Vision alignment:** The label correction is consistent with vision.yaml principle-3 (determinism over judgment for conditionals; if-then logic is code, not instructions) and principle-5 (discriminator improvement over rule addition). The Result Elegance Audit block is consistent with constraint-4 (minimize metabolic cost of cybernetic engagement). No misalignment finding. Stage 1 is confirmed — proceed to Stage 2.

### Gap 3: Result Elegance Audit — advisory gate in a non-promotable location (advisory, not blocking)

The Result Elegance Audit block adds a comment-based soft-gate before the RELAY step in the dispatcher pseudocode. The audit is explicitly non-blocking ("This is not a hard gate — do not block relay"). It asks the dispatcher to apply a heuristic check and emit a `write_observation(category="elegance_signal")` if the output-to-task ratio is high.

The learnings.md entry from 2026-05-14 (PR #1148) states: "Advisory enforcement of structural invariant (idempotency check as markdown instruction) violates vision.yaml principle-3." The key distinction is whether the enforcement condition is purely if-then logic or requires genuine interpretation.

The Result Elegance Audit does require interpretation: "Is each section of this result load-bearing?" is not a string pattern check — it requires semantic judgment about whether content contributes to the response's purpose. The golden-patterns.md advisory-to-hook promotion pattern (2026-04-22) is explicit: "The non-promotable boundary is explicit: gates requiring semantic judgment (Relay filter, Design Gate, Bias to Action) cannot be promoted because no string pattern reliably captures rhetorical priority or message intent."

The Elegance Audit is correctly placed as advisory. It requires semantic judgment; it cannot be a hook. The Relay filter in the same gate table is also advisory for the same reason. This is not a gap — it is correct design.

However, the Elegance Audit block appears in pseudocode syntax (indented under the `# RELAY` comment within a code block) but uses imperative prose rather than pseudocode. Future readers may not know whether this block is executable pseudocode or advisory prose. A note at the top of the block making this explicit ("advisory prose — requires semantic judgment, cannot be promoted to a hook") would improve clarity. This is a note, not a blocker.
