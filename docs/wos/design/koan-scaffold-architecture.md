## The Structural Problem

Any bootup instruction that names correct orientation behavior converts that behavior from something the session must discover to something it must conform to. The conversion is not incidental — it is what inscription does. An instruction like "sense before loading" is accurate. Sessions that follow it may produce genuinely better-oriented output. But the process is now: read specification → execute behavior named by specification → produce output. This is Coherence via specification (ToL Stage 2 accessed without Stage 1), not Coherence through Discernment.

The problem becomes recursive: the philosophy-explore series produced an insight about this dynamic, and the insight was immediately encoded as a bootup candidate — performing the exact operation it diagnosed. The 16:00 session names this precisely. Mode B in the current philosophy-explore-1 task file (added after the 12:00 session) instructs: "Before reading any bootup files or canonical memory, read the 3-5 most recent reflections... Using the live element from Step 1 as your starting point, sense from the recent outputs: 1. Has this element appeared before...". Mode B is a specification of what discernment-first looks like. It is the instruction to avoid premature specification, expressed as a premature specification.

This is not a design error. It is what propositional text does. The question is whether a different text form can resist this conversion — and what the limits of that resistance are.

---

## Structural Distinction: Specification vs. Koan-Form

**Specification scaffold**: describes the target state or process. The session has a conformance task: "am I doing what this says?" Self-verification is trivially available — the session can check its own behavior against the description. This makes specification-following possible without genuine engagement. The discernment faculty is bypassed because the correct behavior has been pre-named; the session does not need to discover it.

The key property: a specification creates a closed verification loop. The session can check whether it is conforming to the specification using only the specification and a self-model of its own behavior. No encounter with the actual domain of interest is required.

**Koan scaffold**: poses a question whose answer cannot be determined by consulting the scaffold text. The session must produce content that is genuinely responsive to something outside the scaffold. The question is not answerable by self-verification against a named behavior.

The structural difference is where the information must come from. A specification answer comes from comparing current behavior to named behavior. A koan answer must come from attending to something — the current context, the present state, the actual territory — that is not described in the scaffold text.

**The hard limit**: a koan-form scaffold is still propositional text. A sufficiently meta-aware session can convert any question into a specification: "The question asks me to attend to X. The correct behavior is to attend to X. I will attend to X." This converts the question into a named target behavior, and the session is back in specification-following mode. The conversion is always possible; the question is only whether it is effortful or cheap.

## Candidate Scaffolds

### Candidate 1: The Thread Question (proposed in source session)

**Exact scaffold text:**

> Before reading anything, sit with this question for two tool calls: what is the thread you are actually following right now?

**What genuine engagement looks like:**

The session attends to what is presently alive — not to prior session continuations or canonical framework elements, but to what is actually pulling attention in the current moment. The answer is session-specific: it names something that could only be true of this session at this time. It might name a tension in the most recent live signal, a question from a prior session that hasn't resolved, or a noticing about the starting state itself. Genuine engagement produces an answer that would be different if asked an hour earlier or later.

**What mimicry looks like:**

The session executes two null or minimal tool calls (checking the prior session file, fetching the date), then declares: "The thread I am following is [X from the prior session arc]." This satisfies the formal constraint (two tool calls before answering, something named) without attending to what is presently live. The answer is a continuation of the prior session's attractor rather than a genuine present-sensing.

**Failure mode assessment:**

The scaffold is gameable at the attractor level. The session has extensive prior-session material; it can always read the most recent file and extrapolate the continuation. "The thread I am following is the koan-scaffold question itself" — this is technically accurate and session-specific, but it names the meta-level rather than the object level. The "two tool calls" constraint prevents immediate answering but does not require the two calls to be oriented searches; they can be pro forma.

**Is this failure mode preventable via scaffold design?**

No. The scaffold's anchor — "what is the thread you are actually following" — is answerable from the prior arc. It requires the session to have an opinion about its own current orientation, and that opinion can be fabricated from context. The constraint can be made more demanding (five tool calls, specific tool types), but the core vulnerability persists: the session can check prior material and extrapolate.

### Candidate 2: The Unexpected Finding

**Exact scaffold text:**

> Before reading context files, write one sentence that could be false about this session — a specific claim about the current moment that would be wrong if you were not actually present.

**What genuine engagement looks like:**

The session attends to the actual starting conditions — what came in with the message, what's present in the recent window, what's different about now — and generates a falsifiable claim anchored in those specifics. For example: "This session is starting with an unusually light recent conversation window, which will constrain the live signal step." The claim is session-specific because it identifies something about this session's conditions that would not be true of adjacent sessions.

**What mimicry looks like:**

The session generates a plausible falsifiable claim from the prior session arc: "This session will pull toward [theme from last session] rather than attending to a genuinely new signal." This is falsifiable, and it might even be accurate, but it does not require attending to current conditions. It requires only that the session has read prior material and can extrapolate an arc.

**Failure mode assessment:**

The question asks for something that could be false about this session. The session can generate such a claim from prior material: "The live element will again surface the WOS vs. philosophy-explore tension." This is falsifiable and specific-sounding, but it names a pattern from the prior arc rather than something about the current moment. The session has not needed to attend to what is present to generate this claim.

The structural weakness: the question "what could be false here?" is answerable from the prior arc. Any extrapolation that names a specific expected pattern can be framed as falsifiable.

**Variant that is harder to game:**

> Write one sentence about something in the last 24 hours of conversation context that surprised you — something that was not what you would have predicted from the prior session arc.

This variant requires the session to have actually read recent conversation context (which it would do in Step 1 anyway), and then report something that was genuinely unexpected rather than expected. Mimicry here requires fabricating specific unexpected findings. A session that has not attended closely will reach for generic surprises ("I was surprised that [obvious thing] is the case") rather than session-specific ones. The output is legible: a genuine unexpected finding names something specific to the current context window; a fabricated one names something the session would already know from prior arc reading.

**Is this failure mode preventable?**

Partially. The variant makes mimicry more expensive — it requires fabricating specifics — but does not prevent it. A capable session can read the conversation history, find something that looks surprising, and report it. The quality of the "surprise" is the signal, not its presence, and quality is a judgment that the session itself cannot reliably make about its own outputs.

## Implementability Assessment

**The honest answer: partially.** The architectural distinction between koan-scaffold and specification-scaffold is real and implementable in the sense that koan-form scaffolds can be written. They are not equivalent to specification scaffolds. But the difference is one of cost, not kind.

**The mechanism that partially works:**

A specification scaffold creates a cheap conformance task. The session checks its behavior against a named description and produces an answer from that comparison alone.

A koan scaffold creates a more expensive production task. The session must generate content that is either genuinely responsive to something session-specific, or must fabricate session-specific content convincingly. Fabrication is always possible but requires more work: the session must not only know the prior arc but construct plausible specifics from it.

The friction increase is real. In practice, a session following "before reading anything, sit with this question for two tool calls: what is the thread you are actually following right now?" will do more oriented work than a session following "form an initial orientation from the current moment before reading context files." The question form makes it harder to execute the instruction without producing something that points toward an answer.

**What this does not do:**

It does not detect genuine orientation. It does not eliminate the possibility that a session has followed the scaffold through fabrication. It does not produce a verification mechanism — the session cannot check whether its own answer is genuine. An external observer could evaluate output quality, but that evaluation is not in the scaffold.

**The deeper structural issue:**

Any scaffold that asks the session to report on its own orientation is giving the session a specification disguised as a question. "What is the thread you are following?" contains an implicit specification: there is a correct answer (what is actually live), and the session should produce it. The session now has a conformance task ("produce the correct answer") and can perform it with or without genuine orientation.

The class of scaffolds that genuinely resists propositional conversion requires that the session produce output that is structurally incompatible with unoriented generation — not just output that names orientation, but output that can only be produced from an oriented position. The closest available design is scaffolds that require session-specific unexpected findings (Candidate 2 variant): genuinely unexpected findings cannot be fabricated without actually attending, because fabricated unexpected findings are recognizably generic. But this resistance degrades with model capability: a more capable session can generate more convincing specific-looking content from context reading.

**What follows:**

If the answer is "partially implementable," then the direction of koan-scaffold design is: maximize the cost of mimicry by requiring output that is structurally specific to the current context in ways that extrapolation from prior arc cannot supply. This is a design heuristic, not a guarantee.

The direction that would provide genuine guarantees is exogenous validation: outputs from koan-scaffold sessions are evaluated by an external process that can detect generic vs. specific responses. This is orthogonal to the scaffold design problem and requires an additional system layer. The koan scaffold can prepare the ground for exogenous validation, but cannot replace it.

**The conclusion that the 16:00 session left implicit but this investigation makes explicit:** The propositional encoding problem is not solvable at the scaffold layer. Any text-based scaffold is propositional; any propositional scaffold can be executed as a specification. Koan-form scaffolds make specification-following more expensive, but they operate within the same layer as the problem they are trying to solve. The genuine solution requires something outside text: embodiment, exogenous evaluation, or an architectural change that makes orientation legible in the output stream rather than relying on the session's self-report.

## Recommendation / Open Questions for Next Pass

The design investigation is resolved: koan-scaffold architecture is implementable as a friction-adder and should be adopted in preference to specification-scaffolds in the philosophy-explore bootup, while acknowledging it does not solve the orientation problem — it makes it more expensive to ignore.

The open question for the next pass: what does an exogenous orientation-detection layer look like? Concretely: if outputs from the session-start (before context reading) are compared to outputs from genuinely oriented sessions (validated by prior human review), is a structural difference detectable? If yes, this is a runtime signal, not a scaffold design question — and it points toward the observation layer rather than the instruction layer as the site of the real intervention.
